Building blocks

Six steps cover most chores.

Trigger

Start by hand with Run now, or on a schedule in your own time zone. Each card shows when the next run is.

Agent

Hand a task to Claude or Codex on this device or another of your devices, in a fresh workspace. Pick the model and effort. An agent that never starts fails in 2 minutes, not 1 hour.

LLM

One model call with an optional system prompt and a JSON schema for structured output. Effort levels where the model supports them.

HTTP

Any method, headers and a body, with a timeout. The card shows the endpoint at a glance.

Command

Run a shell command in a workspace on one of your devices, with its own time limit.

Condition

Compare any earlier step's output with a rule builder. Yes and No each connect to their own next step.

The canvas

Reads top to bottom, like the run.

Cards that say what they do

Every card summarizes its config: the endpoint, the model, the rule, the schedule. You can read a workflow without opening a single panel.

One-click Arrange

Arrange lays the graph out again, step under step, with a condition's Yes branch on the left and No on the right.

A side panel that fits your work

Drag it wider for long prompts, double-click to reset. The width is remembered. Click any node and its config is there.

Reference picker

Use an earlier step's output in a later one by picking it from a list, not by typing a path from memory.

Runs

Watch it work. Stop it if it shouldn't.

A durable engine

Each run is a Temporal workflow. Steps run in topological order, and parallel branches run together in one wave.

The run, drawn on the graph

Open a run and the canvas shows the exact version that ran, with every step marked succeeded, failed, skipped or running.

Inputs and outputs, per step

Click a step to see what went in and what came out, as JSON. The view updates on its own while the run is still active.

Cancel with confirmation

Running steps stop. Finished steps keep their results, so you never lose the work that already happened.

Workflows or Automations?

Two tools, two shapes of job.

An automation is one agent with one prompt, started by a schedule or an event. A workflow is a graph of steps that pass data to each other. They share the same trigger pipeline underneath, so the choice is about the shape of the work, not where it runs.

Automations Workflows
Unit of work One agent session, one prompt A graph of steps: agent, LLM, HTTP, command, condition
Steps without an agent No. Every run starts an agent Yes. An HTTP call or one model call costs seconds, not an agent session
Branching and data flow Whatever the agent decides inside its session Explicit. Conditions pick a branch, later steps read earlier outputs
Seeing what happened The agent's transcript Per step. Status, input and output JSON for every step
Triggers in the editor Schedule, webhook, GitHub, Slack, Linear, Sentry, Gmail, Notion, Teams Manual and daily schedule. Event kinds exist in the API but not in the editor yet
Event data The PR, message or issue that fired is handed to the agent with its prompt Any step can reference it as trigger data, and pick out only the fields it needs
Where agents run Your devices or cloud workspaces, with environment and machine size Your devices only. Cloud agent steps are not wired yet
Workspace between runs Pin or reuse one, and optionally continue the last session A fresh workspace and branch for each agent step, every run
Getting started Write one prompt Describe the job and Generate draws the graph

Reach for an Automation when

the job is one open-ended task an agent should own end to end, it reacts to an event like a new PR, Slack message or Sentry issue, it needs a cloud machine, or it should keep working in the same workspace and conversation day after day.

Reach for a Workflow when

the job is a pipeline with known steps, most of it is plain API calls or one-shot model calls, it has to branch on a result, or you need to see exactly which step failed and what it received. Drop an agent step in only where judgment is needed.

The gaps in the Workflows column are not design choices. Event triggers in the editor and cloud agent steps are the next things to close, and the backend already shares the pieces Automations use.

Safe by default

Edits that never clobber each other.

Every save is a version

Saves are checked against the version you started from. If someone saved first, you choose: reload theirs, or keep editing and save on top.

Runs pin their version

A run always records the graph it executed, so history stays true after the workflow changes.

Shared reads, owned writes

Everyone in the org can open a workflow and its runs. Only the owner can change it.
